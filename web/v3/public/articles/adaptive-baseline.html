A Fixed Threshold Is Always Wrong for Someone

Why "more than 50 requests a minute is suspicious" breaks on real traffic, and how a per-consumer learned baseline fixes both directions of the problem at once.

Enumeration detection — flagging a consumer who's iterating through object IDs faster than a normal user would — sounds simple until you try to pick the number. Set the threshold low, and your busiest legitimate integration partner trips it every morning. Set it high enough that the power user stops tripping it, and a patient attacker enumerating just under your line sails through undetected. There is no single number that's correct for every consumer on a real system, because "normal" isn't one number — it's a distribution across very different callers.

The two failure directions, concretely

ScenarioFixed threshold (e.g. 50/min)
Internal batch job, normally 200 req/minFalse positive, every run
Attacker enumerating at 40 req/minFalse negative, never flagged

Both consumers are on the same gateway, hitting the same endpoint. One fixed number cannot be right for both — the whole premise of a single global threshold is that "normal" is a constant, and it isn't.

What we do instead: learn each consumer's own norm

Rather than a global constant, AEGIS keeps a per-consumer, per-endpoint exponentially weighted moving average of distinct-object access counts, and flags a request only when the current window is an outlier relative to that specific consumer's own history — not relative to everyone else's.

-- folds the current observation into the stored baseline with a small
-- alpha, so the baseline drifts slowly toward the consumer's real norm
-- instead of being knocked around by any single window
local alpha = 0.05
local nb = alpha * cur + (1 - alpha) * b

0.05 means each new window moves the baseline about 5% of the way toward whatever just happened. A single unusual burst barely nudges the long-run average; a sustained change in behavior — the consumer genuinely growing its usage — gets absorbed over time instead of being permanently flagged. And critically: the internal batch job's baseline settles near 200, and 200 is normal for it. Someone else with a baseline near 5 gets flagged for a jump to 30, which the batch job would never trigger on at all.

The part that keeps the baseline honest: don't learn from an attack

An EWMA that learns from every observation, unconditionally, has an obvious hole: an attacker who ramps up slowly enough trains the detector to think the attack is normal. So learning is conditional — a window is only folded into the baseline when it doesn't breach the hard absolute ceiling that exists independent of the adaptive logic:

b, err := st.TrackBaseline(ctx, consumer, endpoint, maxCount, !overCeiling, baselineTTL)

!overCeiling is the whole safeguard in four characters: learn only when this window didn't already blow through the hard ceiling. A clear attack gets flagged by the ceiling and never gets to poison the baseline it would otherwise be measured against next time.

One more failure mode: the empty-history floor

A brand-new consumer with almost no history has a baseline near zero — which means almost anything looks like a huge multiple of "normal" and would trigger constantly on day one. There's a floor for this reason: the adaptive check only applies once a consumer has accumulated a minimum number of observed objects, so a cold-start consumer isn't judged against a baseline that hasn't had time to mean anything yet.

What this doesn't do

  • It's still per-endpoint, not cross-endpoint. An attacker enumerating low-and-slow across many different endpoints, each individually under its own baseline, isn't correlated by this mechanism alone.
  • It's a multiplier on a learned norm, not a percentile model. A true percentile-based model would react differently to skewed distributions; the EWMA-multiple approach is simpler and cheaper to run atomically in Redis, at the cost of some precision.
  • There's still a hard absolute ceiling underneath it — the adaptive layer sits on top of, not instead of, a fixed maximum nobody should ever exceed regardless of their personal baseline.
